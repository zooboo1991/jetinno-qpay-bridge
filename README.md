# Jetinno ↔ QPay bridge

Jetinno JL30 кофены машиныг QPay-тэй холбох middleware. Машин болон QPay шууд харилцдаггүй — энэ сервер дунд нь орж орчуулна.

QPay клиент нь gmath.mn дээр ажиллаж байгаа холболтоос авсан: токен кэш, `payment_status` шалгалт, `cancelInvoice`-ийн `INVOICE_PAID` боловсруулалт бүгд тэндээс.

## Урсгал

1. Хэрэглэгч машины дэлгэцээс кофе сонгоно
2. Машин → `POST /jetinno/getQrCode` (энэ сервер рүү)
3. Сервер → QPay invoice үүсгэж, QR-ийг машинд буцаана
4. Хэрэглэгч банкны аппаараа дэлгэцийн QR-г уншуулж төлнө
5. QPay → `/qpay/callback/:orderNo`
6. Сервер QPay-аас **дахин баталгаажуулаад** машины `notifyUrl` руу `PAYSUCCESS` илгээнэ
7. Машин кофе гаргаад `POST /jetinno/productdone` илгээнэ

## Локал туршилт (QPay-гүйгээр)

```bash
cd ~/Downloads/jetinno-qpay-bridge && npm install
```

Бүтэн урсгалыг автоматаар шалгах:

```bash
npm run test:e2e
```

Энэ нь сервер + дуурайлган машин хоёрыг асааж, дараах 3 зүйлийг батална: кофе яг нэг удаа гарсан, давтагдсан `getQrCode` шинэ invoice үүсгээгүй, QPay callback `200 SUCCESS` буцаасан.

Гараар турших бол — нэг терминал дээр сервер:

```bash
PORT=3100 QPAY_MOCK=1 PUBLIC_URL=http://localhost:3100 npm start
```

Өөр терминал дээр машин:

```bash
BRIDGE_URL=http://localhost:3100 npm run simulate
```

Гарч ирсэн `curl .../mock/pay/TEST...` командыг ажиллуулбал төлбөр орсон мэт болж, "машин" кофе гаргана.

## Бодит QPay-тай холбох

```
QPAY_USERNAME=          # merchant.qpay.mn-аас
QPAY_PASSWORD=
QPAY_INVOICE_CODE=
# QPAY_BASE_URL=https://merchant.qpay.mn   # sandbox бол өөр

JETINNO_USERNAME=       # Jetinno-с (§2.1)
JETINNO_APIKEY=
PUBLIC_URL=https://таны-домэйн             # машин болон QPay хүрэх public https

# AMOUNT_DIVISOR=100    # доорх "нээлттэй асуудлууд"-ыг үзнэ үү
# ABANDON_AFTER_MS=600000
```

`QPAY_MOCK` тохируулахгүй орхино. `GET /health` нь `qpayConfigured` талбараар хувьсагчид бүрэн эсэхийг харуулна.

**Localhost дээр бодит QPay турших.** QPay `localhost` руу callback хүргэж чадахгүй. Туннел (ngrok, cloudflared) хэрэглэхгүй бол төлбөр төлсний дараа гараар:

```bash
curl http://localhost:3100/check/<orderNo>
```

Энэ нь callback-тай яг ижил `settle`-ийг дуудна — QPay-аас баталгаажуулаад машинд мэдэгдэнэ.

## Render дээр байршуулах

Vercel тохирохгүй: захиалгууд санах ойд байдаг тул serverless instance бүр өөр байх нь урсгалыг тасалдаг, `setInterval` sweep ажиллахгүй, Express-ийг дахин бичих хэрэгтэй болно. Байнга ажилладаг процесс хэрэгтэй.

**Free tier сонгож болохгүй.** 15 минут хүсэлтгүй бол унтарч, дараагийн хүсэлт дээр ~30 секунд сэрдэг. Jetinno-ийн хугацаа 8 секунд — шөнөжин зогссон машины өглөөний анхны үйлчлүүлэгч кофе авч чадахгүй гэсэн үг.

1. GitHub дээр repo үүсгэж push хийнэ (доор командууд бий)
2. Render → New → Web Service → тухайн repo-г сонгоно
3. Runtime `Node`, Region `Singapore`, Instance type `Starter`
4. Build `npm ci`, Start `npm start`, Health check path `/health`
5. Environment дээр `QPAY_USERNAME`, `QPAY_PASSWORD`, `QPAY_INVOICE_CODE`, `JETINNO_USERNAME`, `JETINNO_APIKEY` нэмнэ

`render.yaml` мөн байгаа (Blueprint хэлбэрээр), гэхдээ дашбоардаас гараар үүсгэх нь алдаа гаргах магадлал багатай.

`PUBLIC_URL` тохируулах шаардлагагүй — Render-ийн `RENDER_EXTERNAL_URL`-ээс автоматаар авна. Deploy хийсний дараа `https://<нэр>.onrender.com/health` дээр `qpayConfigured: true` гарч байвал бэлэн.

Jetinno-ийн маягтад бичих гурван хаяг:

```
https://<нэр>.onrender.com/jetinno/getQrCode      → qRUrl
https://<нэр>.onrender.com/jetinno/refund         → refundUrl
https://<нэр>.onrender.com/jetinno/productdone    → callbackUrl
```

## Endpoint-ууд

| Зам | Хэн дуудна | Тайлбар |
|---|---|---|
| `POST /jetinno/getQrCode` | Машин | Invoice үүсгэж QR буцаана |
| `POST /jetinno/productdone` | Машин | Кофе гарсан эсэх |
| `POST /jetinno/refund` | Машин | Одоогоор `ERROR` буцаана — QPay буцаалт хараахан холбоогүй |
| `ALL /qpay/callback/:orderNo` | QPay | Үргэлж `200 SUCCESS` |
| `GET /check/:orderNo` | Та | Гараар баталгаажуулах |
| `GET /orders/:orderNo` | Та | Захиалгын төлөв харах |
| `GET /health` | Та | Тохиргоо бүрэн эсэх |

## Яагаад ийм бичсэн бэ

**`settle` дотор `settling` тугийг `await`-аас өмнө синхроноор тавьдаг.** QPay-ийн webhook болон `/check` хоёр яг нэг агшинд ирдэг нь бодит зүйл. Туггүй бол хоёул төлөв шалгалтыг давж, хоёул машинд мэдэгдэж, **нэг төлбөрт хоёр кофе** гарна. `npm run test:e2e` үүнийг 5 зэрэгцээ дуудлагаар шалгадаг — зөвхөн нэг нь 200 авах ёстой.

**Машин кофе гаргасныг баталсны дараа л `paid` болгодог.** Мэдэгдэл амжилтгүй бол захиалга дахин оролдох боломжтой хэвээр үлдэнэ — эс бөгөөс мөнгө авчихаад кофе өгөхгүй.

**Давтагдсан `getQrCode` хадгалсан QR-аа буцаана.** Машин 8 секундэд хариу аваагүй бол дахин асууна. QPay нэг `sender_invoice_no`-г хоёр дахь удаа хүлээж авахгүй тул шинэ invoice үүсгэж болохгүй.

**QPay callback үргэлж `200 SUCCESS`.** JSON эсвэл алдааны код буцаавал QPay давтаад байна.

**Төлөгдөөгүй QR-ыг 10 минутын дараа цуцалдаг.** Эс бөгөөс хэрэглэгч орхиод явсан QR сар хагасын дараа төлөгдөж, машин аль хэдийн мартсан захиалганд кофе гаргахгүй. Цуцлахад QPay `INVOICE_PAID` гэвэл тэр хүн үнэндээ төлсөн тул цуцлахын оронд гүйцээнэ.

## Нээлттэй асуудлууд

- **QR 128 тэмдэгтийн хязгаар — 2026-08-12-нд бодит утсаар батлагдсан.** QPay-ийн `qr_text` (банкны апп уншдаг жинхэнэ төлбөрийн QR) нь **242 тэмдэгт** — Jetinno-ийн 128-д багтахгүй. Харин `qPay_shortUrl` (27-28 тэмдэгт) багтдаг ч **банкны аппын QR уншигч татгалздаг** (QP2016 "QR код олдсонгүй") — учир нь энэ вэб холбоос, төлбөрийн код биш. Гарц: (а) Jetinno-с хязгаарыг ≥256 болгохыг хүсэх — үндсэн зам; (б) богино URL хэвээр үлдээж хэрэглэгчид **камераар** уншуулах — камер хөтчөөр QPay-ийн төлбөрийн хуудсыг нээж, тэндээс банк сонгож төлнө.
- **`orderAmount` нэгж.** Jetinno цент-ээр (100000 = 1000₮) илгээнэ гэж үзээд 100-д хуваасан. Бодит машины эхний `getQrCode` логийг хараад `AMOUNT_DIVISOR`-ыг тохируулна.
- **Хариу мессежийн гарын үсгийн талбарууд.** Баримт бичигт хүсэлтийн жишээ л бий, хариунд аль талбарууд орохыг заагаагүй. `src/sign.js` дахь `getQrCodeResponse` жагсаалтыг машинтай тулгаж баталгаажуулах хэрэгтэй.
- **`nonce`.** Баримтын §2.4 дурддаг ч ямар ч параметрийн хүснэгтэд байхгүй. `verifySign` нь ирсэн бол ашиглаж, эс бөгөөс алгасдаг — машины эхний хүсэлт үнэнийг хэлнэ.
- **Refund.** `/jetinno/refund` одоогоор `ERROR` буцаана. QPay-ийн буцаалттай холбох нь дараагийн алхам.
- **Олон эзэмшигч.** Машин зарах загварт машин бүрийн мөнгө өөрийн эзэмшигчийн QPay данс руу орох ёстой. Одоо нэг л мерчант дэмжинэ — `deviceNo` → QPay түлхүүрийн бүртгэл нэмэх шаардлагатай.
- **Санах ойн хадгалалт.** Захиалгууд `Map` дотор. Сервер дахин асахад төлөгдөөгүй захиалгууд алга болно. Нэг машины эхний туршилтад хангалттай, production-д өгөгдлийн сан хэрэгтэй.
